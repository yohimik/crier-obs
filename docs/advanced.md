# Use a base configuration

The normal mode writes a generated JSON configuration for every run. It sends the plugin's effective defaults, including the bundled card, 1080 × 1080 PNG and hermetic fonts. The full [crier reference](https://github.com/yohimik/crier/blob/v1.1.1/docs/configuration/README.md) explains every setting.

Select a **Base configuration file** in **Advanced** to use an existing YAML, JSON or TOML file. Crier runs with `--config <base>` and repeated `--set key=value` overrides. For keys you have not changed in the dialog, the base file wins. A value you change stays explicit, including when you change it back to crier's registry default. OBS's Defaults action resets the dialog settings. The script always supplies all destination enables, its per-event caption, the selected data document and safety settings needed for that invocation. See [crier precedence and --set](https://github.com/yohimik/crier/blob/v1.1.1/docs/configuration/README.md).

Before an advanced post, the script asks crier to inspect the base configuration asynchronously. It explicitly disables custom destinations found only in that file, so an unseen destination cannot publish behind an unticked dialog. A fingerprint detects a base file changed during these checks or before posting; the run is skipped and reported if the snapshot no longer matches. The quit trigger uses the destination list already checked for the live session and skips when that check is unavailable.

Lists are JSON arrays in generated mode. In advanced mode, crier's command-line list representation is comma separated. A literal comma inside one item cannot be represented by `--set`; move that list into your base file. Advanced command line overrides may be visible to process inspection tools such as `ps`. Credentials stay in environment variables.

Paths in a base file resolve according to [crier's configuration rules](https://github.com/yohimik/crier/blob/v1.1.1/docs/configuration/README.md). The script runs advanced invocations from the base file's folder. An explicit **crier path override** takes precedence over the private installation and PATH search. OBS launched from Finder or the Start menu may have a different PATH than a terminal; discovery adds common install folders.

Linux Flatpak or Snap packages can isolate OBS from host tools and Secret Service. The script reports sandbox restrictions in **Check setup**. The host bridge uses `flatpak-spawn --host` with a separate environment pipe; credentials are never put in `--env` arguments. It clears the inherited host environment and requests host-command cleanup when the helper exits. This requires a current Flatpak host portal, a helper supporting `--env-fd`, and configuration, templates, media and state paths under the shared home directory. Very old portals that silently ignore `--watch-bus` are unsupported. Unmappable sandbox paths produce an explicit setup failure. An older helper may reject `--env-fd`; update it or run a native OBS package. See the [Flatpak helper source](https://github.com/flatpak/flatpak-xdg-utils/blob/main/src/flatpak-spawn.c) for its environment descriptor contract.

Run timeout, retention count and retention age are in **Advanced**. Debug logging adds state transitions and process metadata. It never intentionally records credential values.

Linux spawning requires glibc 2.34 or newer, which introduced the [atomic close-from spawn action](https://sourceware.org/pipermail/glibc-cvs/2021q3/073654.html). Older libraries fail with a descriptor-isolation setup error instead of allowing OBS sockets to leak into a child.
